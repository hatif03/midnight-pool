The Midnight pool hall: hang with friends, compete ranked, and prove you're good enough — without ever revealing your stats.

## 2. About the project

### Inspiration

Midnight is building a chain where you can *prove* something without *showing* it. Almost every game on a public ledger does the opposite: leaderboards, wallets, win rates, and wager history sit in the open. That's fine for a high-score site. It's a terrible hangout.

Pool halls aren't spreadsheets. They're places you show up with friends, take a table, talk trash, play a ranked set, and leave without the whole room knowing your bankroll or your exact record. That's the product we wanted: **a social table for people on Midnight** — not a DeFi wrapper with balls on it.

The "before" state already existed: a real 2D 8-ball game (PixiJS, custom physics, PeerJS 1v1). The hackathon question was: what does that game become when the chain is Midnight instead of a public EVM scoreboard?

Three tracks, one answer:

- **Mobile** — a real installable PWA, because a hangout you can only open on a laptop isn't a hangout.
- **Integrate Midnight** — private ranked credentials, soulbound cosmetics, a fair break, and match-result attestation, without the game ever blocking on a proof server.
- **Cross-chain** — a rank you prove privately on Midnight can mint a badge on EVM, with **no bridge** and no custody.

### What it does

Midnight Pool is a mobile-first 8-ball PWA. You install it, drag-shoot on a phone in landscape, and play:

- **Solo** practice
- **Invite a friend** (4-letter code, share link, or QR)
- **Quick Match** against a stranger (WebSocket relay on Cloud Run; game traffic stays peer-to-peer)

On top of that, Midnight is the *privacy layer of the hangout*, not a loading spinner:

**Private ranked play.** Your level and wins live as a commitment (`commitStats`). To enter ranked Quick Match, or to light up a league badge (Brass → Diamond), you run `proveThreshold`: the chain learns *yes or no* — never the number. Friends can know you're Gold. They never see 60–20 / 75%.

**Soulbound cues, not tradable NFTs.** Cue ownership today is a `localStorage` field anyone can edit. `claimCue` spends a nullifier into an on-chain set: you can claim a tier once, you can't sell it, and nobody else sees which cue you unlocked. Cosmetics as identity, not a marketplace.

**A fair first break.** Hosts used to always break (a real statistical advantage). Both sides now commit a nonce, reveal, and combine — over PeerJS so the rack starts in milliseconds, and fire-and-forget on-chain so the flip is also an audit record. If someone stalls, they lose the flip; last-revealer bias is closed.

**Match stakes in practice Coins.** Not real money. Both sides open a stake; the first on-chain attestation of the winner is write-once and final. A host who goes silent when losing can't overwrite the guest's honest claim. Coins never go negative.

**Guest-side physics check.** The host still runs physics (that's how P2P pool has to work at 60fps), but now broadcasts the pre-shot snapshot + inputs. The guest replays the same deterministic loop and diffs the result. A fabricated shot shows up in the Midnight Activity log.

**Server-signed receipts.** After a match, both peers attest to the relay. Once two sides agree, you can fetch an HMAC-signed `(pk, level, wins)` receipt and disclose it *alongside* the ZK commitment — a first step toward "this number wasn't just typed in."

**Cross-chain Champion Badge.** If `proveThreshold` says you qualify, a Foundry `ChampionBadge` contract on a local EVM chain mints. If you don't, it doesn't. **No bridge**, no custody — two chains independently read and joined by a shared key. We built two versions of this join: a fast one (Midnight side via the compiler's own simulator, no network needed) and a fully real one — an actual `MidnightPool` contract deployed to a running local Midnight network, a real ZK proof generated by a real proof server, a real confirmed on-chain transaction, joined with the same real `anvil` mint. Both qualifying and non-qualifying outcomes verified on the real version. The same circuit also runs *in the browser* via `@midnight-ntwrk/compact-runtime` WASM so you can see the proof locally in Settings.

**Installable, offline-capable PWA — and it actually asks you to install it.** Manifest, service worker, generated icons, landscape lock, touch-first HUD, English/Spanish, sensitive keys and proof inputs staying on device. On Android/Chrome, a real install banner appears via `beforeinstallprompt`; iOS Safari has no such API, so it gets a "tap Share → Add to Home Screen" instruction instead. Skipped once already installed, dismissible, never shown on desktop.

### How we built it

We kept the existing game as the Integrate Midnight "before," and layered Midnight in as a thin, fire-and-forget bridge — the shape of Among-Midnight's Shadow Protocol, with one deliberate correction: **proofs run in the browser**, not on a server that can still read secrets.

**Contract (`contracts/midnight-pool.compact`).** One Compact contract, six circuits, compiled with full ZK keys. Every circuit executed (34 simulator checks), not just compiled. Compact has no XOR/modulo and no readable block height — only block-*time* comparisons — so the break flip is `persistentHash(...)[0] < 128`, and deadlines are Unix seconds. Exported parameters are treated as private by the disclosure analysis, so even `matchId`/`role` need explicit `disclose()`. A real soundness bug (nonce minted *inside* a witness, so a proof retry would seal a commitment it could never open) was caught by `witness-verifier` and fixed before we called it done. Compact CLI doesn't exist for Windows; compile lives in WSL, tests run natively.

**Stakes (`contracts/stakes.compact`).** Originally designed as "timestamped 2-of-2, first attestation wins on timeout." Compiling proved you **cannot store block time as data** — only compare it. We replaced that with a write-once ledger cell: whoever lands first is permanently canonical. Same exploit closed, simpler circuit. 12 execution checks, including "a late self-favoring host claim cannot displace the guest's earlier honest one."

**Frontend (`src/midnight/`).** `hooks.js` is mock-mode by default so a missing wallet never stalls a shot. Real mode logs "not wired" instead of faking a tx. `circuit.js` dynamically imports the compiled WASM (~1.4 MB) only for the Champion Badge panel, so live gameplay stays synchronous. `wallet.js` talks to `window.midnight` (Lace / DApp Connector) with no extra SDK. `breakOrder.js` is a SHA-256 commit-reveal over the existing PeerJS channel. `audit.js` is a local activity log you can actually show a judge.

**Cross-chain.** We attempted the full Effectstream `evm-midnight-v2` stack (Midnight's recommended engine). Got genuinely far: EVM deploy on Hardhat, a real local Midnight devnet producing blocks, indexer and proof server up. Then six environment bugs in a row (Bun symlink hell, Nix-hardcoded interpreter paths, `graphql@17` bun export, compiler/runtime pin mismatch, WASM module-identity duplication). Per the ADR we wrote *before* starting, we fell back to a lighter join: real `proveThreshold` + real `anvil` mint, both directions verified.

Later, once the deadline pressure was off, we went further and made the Midnight side of that join genuinely real too — not just the simulator. Midnight's own compatibility matrix (fetched, not guessed) pins `midnight.js@4.1.1` to `compact-runtime@0.16.0`; our contract had been compiled against `0.19.0` for the browser bundle. Fixing it took: an isolated npm package (Node resolves a compiled contract's imports by *the file's* location in the tree, not the importing script's, so the matched runtime has to live *inside* that package); lowering an accidentally-too-high `pragma language_version` (the contract's actual syntax only ever needed 0.23, verified by compiling a copy before touching the real file); and deduping two WASM class-identity conflicts (`ledger-v8`, `onchain-runtime-v3`, each with two differently-versioned nested copies) via npm `overrides` — the exact same failure class as Effectstream's WASM bug above, except this time we recognized the pattern immediately and fixed it in minutes, not hours. Result: a real deploy, a real `commitStats`, a real `proveThreshold` — genuine `contractAddress`/`txId`/`blockHeight` — joined with the same real EVM mint.

**Mobile.** `vite-plugin-pwa`, landscape overlay (iOS won't lock orientation), HUD that doesn't cover the table, clamp-based menu that fits a 360px-tall phone. Live at Vercel; matchmaking on Cloud Run.

We wrote an ADR before every structural decision. Compact syntax was never trusted from memory — Midnight's own docs say the language isn't in training data, and they were right.

### Challenges we ran into

**The language is real, and it is not Solidity.** No native Windows Compact CLI. No XOR. No modulo. No block height. You cannot *read* block time, only compare it. Disclosure analysis treats circuit parameters as private. Witnesses that aren't pure reads of private state will bite you on retry. Every one of those was discovered by compiling, not by recalling a tutorial.

**Client-side proving vs. "the game has to feel like a game."** A WASM cold-start in the middle of a break shot is a product failure. We split the world: fast hand-rolled mocks on the gameplay path, real compiled-circuit execution in an isolated Settings panel, P2P commit-reveal for who-breaks-now, on-chain record fire-and-forget.

**Host-authoritative physics vs. "provably fair."** A fully lockstep, fixed-point simulation was a multi-day rewrite. We shipped deterministic guest replay with an epsilon for `Math.hypot` drift, and we say out loud what it does *not* prove (the host can still lie about the *inputs*).

**Garbage in, provably out.** ZK proves a *relation* about a commitment, not that the number is true. We added 2-of-2 relay attestation and signed receipts rather than pretending `commitStats` is anti-cheat. We will not demo this as "you can't cheat."

**Effectstream and Preprod.** The recommended cross-chain stack almost worked and then died on a WASM identity collision. A time-boxed Preprod attempt got a proof server running, indexer and node confirmed live — then `WalletFacade` leaked memory in a `subscribeRuntimeVersion()` reconnect loop until the process OOM'd. We stopped inside the time-box, documented it, and moved on.

We came back to it once the deadline pressure was gone and finished the diagnosis properly. Two controlled experiments nailed it down: a local-devnet control run (same code, same log line, syncs fine on a near-empty chain) ruled out the reconnect noise itself as the cause; swapping in a no-op transaction-history store that crashed at the identical rate ruled out the one configurable suspect. What's left: `wallet-sdk-facade`'s own sync-state tracking leaks memory linearly with the number of processed ledger entries. We queried Preprod directly — it's at block 2,330,285 — and the math doesn't close: completing a sync at the observed leak rate would need on the order of hundreds of GB of RAM. Not a patience problem. We filed a complete, reproducible report upstream ([midnightntwrk/midnight-wallet#704](https://github.com/midnightntwrk/midnight-wallet/issues/704)) with exact versions, the instrumented reproduction, and both control experiments, rather than leaving "it crashed" as the final word.

**Our own build tooling lied to us once, too.** Vercel deploys started failing with a Rolldown native-binding stack trace. We spent real time chasing it as a Node-version problem (added an `engines` pin — reasonable, still wrong). The actual error was one frame further up, hidden until we got real `vercel inspect --logs` access: a browser-only file imported a path our own `.gitignore` excluded, so a fresh clone never had it. Fixed by committing the 160KB of compiled contract JS the browser actually needs (not the 28MB of ZK keys it doesn't) and verifying with a genuine fresh clone in a Linux container before trusting it. The lesson generalized to the Midnight side too: don't diagnose from a stack trace's *shape* — get the real, complete error before you fix anything.

**Disk, WSL, and a weekend clock.** A 38 GB npm cache and a leftover native `.bun` install ate the Windows drive mid-hackathon. Midnight binaries are linux/mac only. Deadline was 11:45am EDT.

### Accomplishments that we're proud of

- A **real game people can actually play**, with Midnight features that don't get in the way of the next shot.
- **Selective disclosure used correctly**: ranked gates and league badges disclose a boolean; soulbound cues use a nullifier set; league standing is *ephemeral* (it must be allowed to drop) — reusing the cue pattern there would have been a category error.
- **Client-side proving in a browser PWA**, which is literally the Mobile track's sentence: sensitive information never leaves the device unproven.
- Finding the Compact time/XOR/witness bugs **by compiling**, and changing the stakes design because the original one was physically inexpressible.
- Guest physics verification with a real two-browser Playwright pass: `ok: true, mismatchCount: 0` on an actual break.
- Attempting Effectstream and Preprod for real, documenting the crashes, and shipping a fallback that still joins two chains without a bridge.
- **A real deploy, not a demo of one**: genuine `deployContract`/`callTx` against a live local Midnight network — real ZK proof, real transaction, real block confirmation — joined into the cross-chain flow with both outcomes (qualifies / doesn't) independently verified.
- Root-causing the Preprod `WalletFacade` crash precisely enough to file a complete, reproducible bug report upstream, instead of leaving an unexplained OOM in the repo.
- Honesty in the ADRs. "Provably fair wagering" would have been a better tagline and a lie. We didn't use it.

### What we learned

Midnight's privacy primitives (commitments, selective disclosure, nullifiers, domain-separated hashes) are a **better fit for a social game than for a public leaderboard**. The interesting design work is choosing which proof pattern matches which social object: a cue is soulbound, a league badge is not, a break flip has to be low-latency *and* auditable, a stake cannot wait on a timeout you can't store.

We also learned that "never blocks the game" is a product constraint, not an implementation detail. If the chain is slow, the hangout still has to work. Mock-mode-by-default, fire-and-forget hooks, and dual-path break order are how you keep a pool hall feeling like a pool hall.

And: Compact will punish you for assuming it works like every other contract language. That's not a complaint so much as the actual skill the weekend taught.

### What's next for Midnight Pool

The vision is **the place people on Midnight go to hang, compete, and play with their friends** — a table, not a dApp demo.

**Voice at the table.** Next up: in-match voice so friends can talk during a game the way you do over a real felt. WebRTC already carries the match; the same peer connection is the natural place for an audio track. Push-to-talk, mute, and "table open / table private" so a ranked stranger match doesn't dump you into an open mic. That's the difference between a game and a hangout.

**Clubs, seasons, and a living hall.** Clubs/leaderboards were dropped three times this weekend on purpose — they need shared membership and aggregation, and we only just added a thin attestation backend. Next increment is a `clubs` table on the existing relay, weekly seasons, and private club ranks (prove you're Diamond to the club, not to the world). Tournaments with a Midnight-gated entry list.

**Real chain, real receipts.** The local half of this is done: a real deploy, real circuit calls, real cross-chain join, all confirmed on-chain against a live local Midnight network. Preprod is the remaining step, and it's genuinely blocked on us, not on effort — a real `wallet-sdk-facade` memory leak we root-caused and filed ([midnightntwrk/midnight-wallet#704](https://github.com/midnightntwrk/midnight-wallet/issues/704)). Once that's fixed upstream (or we get time to try the browser/Lace DApp Connector path, which uses different sync machinery and may not share the bug), the same `devnet-deploy/` code points at Preprod's real indexer/node/proof-server with a one-line config change. Then in-circuit verification of the server's stat signature, so "garbage in" stops being a known hole and becomes a closed one. After that: optional NIGHT/DUST stakes for people who want them, still behind a ranked credential, still never required to play.

**Grow *with* Midnight, not adjacent to it.** As Midnight ships better web proving, Lace/DApp Connector, and (eventually) mainnet, this app should be a consumer surface those tools land on:

- **Testnet → mainnet:** same circuits, real shielded values, same "game never waits on the indexer" contract.
- **Identity:** passkeys / Sigil-style embedded wallet so installing the PWA *is* getting a Midnight identity, no extension scavenger hunt.
- **Cross-chain reputation:** persistent Effectstream-style sync (the pattern we believe in, even though the full stack didn't stabilize this weekend) so a Champion badge on EVM, a Cardano handle, or a Solana profile can be *joined* to a Midnight credential without bridging funds.
- **Developer gravity:** open the Compact contracts, the audit dashboard, and the mock/real split as a reference for other games — "here's how you add Midnight to an existing multiplayer app without making it unplayable."
- **Community:** Quick Match as the Midnight community's casual queue; private tables as the default way two people on the network spend twenty minutes together. Voice + clubs + seasons turn that from a weekend demo into a habit.

If Midnight is a privacy network, it needs rooms, not just rails. Midnight Pool is trying to be one of the rooms.

## 4. Tell us more about your experience working with Midnight

**What we liked**

The *idea* of Midnight is unusually well-matched to a game. `disclose()` a boolean and keep the number private is not a gimmick here — it's the difference between "ranked play" and "doxxing your record to sit at the table." `persistentCommit`, nullifier sets, and domain-separated hashes are the right primitives. The docs' warning that Compact is barely in training data is the most useful sentence in the whole toolchain: we treated every recalled API as guilty until compiled.

The `midnight-expert` plugin set (compact-core, compact-examples, midnight-verify, witness-verifier) actually caught a soundness bug we would have shipped. Client-side proving via `@midnight-ntwrk/compact-runtime` in a browser is the Mobile track's sentence made concrete. Effectstream's *philosophy* — join two chains off-chain, don't bridge custody — is the correct cross-chain story even though the full stack didn't survive our weekend.

Fire-and-forget + mock-mode-by-default let us keep shipping a playable game while the chain story matured. That's a product lesson Midnight teams should steal.

**What was hard**

Compact is not "Solidity with privacy." No Windows CLI. Linux-only node/indexer/proof-server binaries. No XOR, no modulo, no block height, and you cannot store "current block time" as data — only compare a caller-supplied timestamp. Disclosure analysis surprised us: even public protocol fields needed `disclose()`. Witnesses that mint randomness produce unopenable commitments on retry.

The JS/wallet side is a different kind of hard. `WalletFacade.init` against live Preprod entered a `subscribeRuntimeVersion()` reconnect loop that turned out to be a real memory leak, not noise — confirmed by controlled experiments and precisely quantified against Preprod's actual chain height (2,330,285 blocks; the observed leak rate would need hundreds of GB of RAM to finish a sync). We filed it ([midnightntwrk/midnight-wallet#704](https://github.com/midnightntwrk/midnight-wallet/issues/704)) rather than leave it as "it crashed." The adapter from WalletFacade to the `WalletProvider` / `MidnightProvider` that `deployContract` actually wants is not documented in the plugin skills we had — we found it in `compact-cli-dev`'s CLI template instead. DUST accrual after a faucet grant is a real-world wait we never even reached. Compiler vs `compact-runtime` version pins in third-party templates were wrong relative to their own READMEs.

Even once we got a real local deploy working, the SDK's own package tree fought us: `midnight-js-contracts` needs `compact-runtime@0.16.0`; the browser bundle needs `0.19.0`. Fine — except `midnight-js-contracts` *also* nests two more silently-mismatched copies (`ledger-v8` 8.1.0 vs the top-level 8.1.1, `onchain-runtime-v3` 3.0.0 vs 3.1.0), and each mismatch fails as an opaque WASM `_assertClass` error with no version numbers in it. This is the exact same failure class as Effectstream's WASM bug, except this time it was inside `@midnight-ntwrk/midnight-js-contracts` itself, not a third-party template — so it's not a one-off, it's a pattern the whole SDK surface has.

Effectstream `evm-midnight-v2` asked for a local universe (Bun, Hardhat, PGLite, Nix-built proof server). We fixed six environment bugs in sequence — stale workspace symlinks, missing `.bin` shims, a `/nix/store/...` interpreter path on a non-Nix machine, a `graphql@17` `"bun"` export that pointed `require()` at ESM, a circuit/runtime mismatch, then a WASM `ContractMaintenanceAuthority` instantiated from two nested copies of `compact-runtime`. That's not "we didn't try." That's "we got to the last step and the module graph ate the deploy."

**What would make it even better**

1. **A Windows-native Compact CLI** (or a first-class WSL-free story). "Compile in Linux" is a tax every web hackathon team will pay.
2. **Readable block time / a documented "who was first" pattern.** We invented write-once cells because the language couldn't express the design in the ADR. That's fine once; it shouldn't be a rite of passage.
3. **A documented, copy-pasteable web path:** Lace connect → in-browser prove → `callTx` on Preprod, with one pinned package set that doesn't OOM on `subscribeRuntimeVersion`. The Android/Kuira work is ahead of the PWA/web story; that's the gap we lived in.
4. **Effectstream (or an official join) that boots in an afternoon**, with one `compact-runtime` copy in the tree. The no-bridge design is the right design. The install is not yet a weekend-shaped install.
5. **One `ledger-v8` / `onchain-runtime-v3` / `compact-runtime` version, everywhere, inside `@midnight-ntwrk/midnight-js-contracts` itself** — not just in third-party templates. We hit two more silent nested-version mismatches getting a real *local* deploy working, each surfacing as a WASM error with no version number in it. `npm overrides` fixed it in minutes once we knew to look; a first-run developer won't know to look.
6. **Faucet / DUST that a demo can survive.** If tDUST isn't usable until NIGHT is delegated and DUST accrues, say so in one place with a time estimate, and give hackathon faucets a fast path.
7. **Keep being honest in the docs.** "Don't trust model memory" saved us. More pages like that — especially "witnesses must be pure reads," "parameters are private until disclosed," "you cannot store block time" — would have cut hours.

We still want to build on this stack. The privacy model is the reason the product makes sense. The weekend was the toolchain catching up to the idea.

## 5. What was the most interesting thing you learned at the Midnight Hackathon?

**A zero-knowledge proof is not a truth machine — it's a relation machine. The interesting product work is choosing which social object gets which relation, and never making the player wait for it.**

We went in thinking "put stats on Midnight." We came out knowing:

- `proveThreshold` is perfect for **ranked entry** (disclose a boolean).
- A **soulbound nullifier** is perfect for a cue (you shouldn't sell your stick; you also shouldn't lose it on a losing streak).
- The **same pattern is wrong for a league badge**, because standing has to be allowed to drop — so leagues re-prove on demand, they don't mint a forever-claim.
- A **commit-reveal** is perfect for who breaks, but the *game* cannot wait on an indexer, so the same protocol has to run twice: once over WebRTC for latency, once on-chain for the record.
- **Escrow that needs "who attested first"** cannot be built by storing block time, because Compact won't give you block time as data — the ledger's write-once order *is* the clock.
- And none of it matters if the next shot hitch-waits on WASM. **Client-side proving only wins if it stays off the critical path of the hangout.**

The second interesting thing is smaller and meaner: **last-revealer bias**. A naive coin flip on a chain is not fair. Whoever reveals second can abort. The fix (miss the deadline, you lose) is obvious *after* you've been bitten. We caught it in design review before writing Compact, and it changed how we think about every two-party protocol on a privacy chain.

That's the hackathon: Midnight doesn't make games honest by existing. It gives you a small, sharp set of proofs, and the craft is matching them to how people actually sit at a table.
